# 第053讲 实验指南

## 1 你要复现什么

本实验比较同一回归模型族的三条调参路线：6点子网格、6次不放回随机搜索、12→4→1逐次淘汰。每条路线每份数据请求1080棵搜索树，另加60棵最终重拟合。你要交出预算账本、全部失败、逐份测试误差和不能成立的结论，不是挑一个最高分截图。

直接先修007、026、051至052。零基础读者先用纸笔完成第三节，再运行现成脚本，最后追踪一个候选的三折记录。全部数据在本包内合成，不需要账号、网络数据、GPU或付费API。CPU单线程运行；本机一次主实验约二十余秒，不承诺其他机器的耗时。

## 2 环境与路径

建议Python 3.12。requirements.txt固定数值库版本；可用Anaconda建立独立环境。先在终端切换到本讲目录，确认能看见experiment.py及data/draws.npz。Windows中激活方式以本地Anaconda配置为准，以下命令使用相同Python解释器。

```bash
conda env create -f environment.yml
conda activate ml053
python experiment.py --out outputs/my-result.json
python audit.py --report outputs/my-result.json --out outputs/my-audit.json
python plots.py --report outputs/my-result.json --directory outputs/my-figures
```

已有Python环境时可执行python -m pip install -r requirements.txt。使用python -m pip可避免“pip装到另一个Python”的常见问题。不要只安装最新版本后把不同结果当成算法不稳定；先核对版本、数据和种子。

程序的输入路径由脚本文件位置决定，不依赖终端当前目录；显式--out则相对你调用时的目录。输出默认进入outputs，不覆盖原始数据和交付结果。若系统主目录只读，设置MPLCONFIGDIR、IPYTHONDIR到可写目录即可。

PDF重建另需build-requirements.txt、Node.js、MathJax3.2.2以及Noto CJK字体与Pango。数字实验不需要这些排版依赖。安装完成后bash build_all.sh同时重建实验、审计、Notebook、图和PDF；脚本不自动安装，也不覆盖交付文件。

## 3 L1 先建立一个没有模型的预算表

在纸上写每条路线的候选数、每候选资源、折数及是否从头训练。网格与随机都是6×60×3。淘汰必须分轮写成12×15×3、4×30×3、1×60×3，再求和。最后每条路线再加一次60棵重拟合。

现在假设第2轮严格复用第1轮模型，第3轮也严格续训，分别只增加15与30棵。这一反事实预算是多少？为什么不能把反事实公式用于当前程序？最后解释1080棵相等，实际秒数仍不同的至少两个原因。

验收：写出1080与1140，写出续训反事实810棵搜索预算，并指出当前程序每次新建RandomForestRegressor，没有warm_start。因此搜索预算不能写成810。

## 4 L2 检查数据生成与封存边界

打开data/README.md和data/protocol.json。每个Xr为600×10数组，每个yr为600维。行0至239开发，240至599测试。种子5300至5305生成独立数据，不是把同一份数据随意重分六次。

用Notebook的形状单元确认维度，然后手工查看生成式：2x0是线性项，1.5(x1²−1)是中心化平方项，x0x2是交互项，ε是独立噪声。问自己：树是否直接得到这条公式？哪几列是纯噪声？为什么不同份的有限测试MSE会波动？

打开choose函数。它只接收240行。外面的run在所有搜索结束后才拟合最终模型、读取测试标签算误差。不要改成传入完整600行后在内部“记得不看”；明确接口能减少误用，但接口本身并不替代审计。

验收：画出一份数据的权限图，标出折内训练160、验证80、开发重拟合240、测试360。修改测试标签后，选择出的超参数必须不变。

## 5 L3 追踪一个候选的三次拟合

运行主实验后打开outputs/my-result.json。runs中每一项是一种方法、一份数据的完整搜索。选rep=0、method=grid的candidate=0，找到它三个fit记录。不要把runs的顺序误认成候选顺序。

每条fit有train_ids、valid_ids、resource、prediction、mse、seconds等字段。检查训练与验证行不交叠且合计覆盖0至239。prediction按valid_ids的顺序保存，因此第一个预测对应valid_ids的第一个行号，不必然对应全表第0行。

用纸笔或列表循环重算一个MSE：依次取该行真实标签减预测，平方，加总，再除80。然后取三折MSE平均。三折相同大小，所以等权折平均也等于全部240个留出误差平均；若折大小不等，这两个口径可能不同，必须说明想估计什么。

验收：写出三折MSE及平均，说明为什么训练集彼此重叠，不能把三个分数当三份完全独立数据。audit.py对全部522次主要搜索拟合完成同类算术核查。

## 6 L4 从候选排序复算淘汰

在rep=0、method=halving中读取configurations、stages和fits。第一轮12个候选各得到一个三折平均，排序后保留前4。第二轮仅这4个以30棵重新拟合，保留1个。第三轮只有1个，以60棵再次评估。

从第一轮的ranking读取前4个candidate，再检查第二轮实际fit的candidate集合完全相同。对第二到第三轮也做相同检查。若某个早已淘汰的编号重新出现，说明日志或调度有错；不要仅凭总拟合次数正确就宣布通过。

对图3只读实际点。淘汰候选没有后续分数，不能推测它若继续训练一定更差。再读图4构造反例：slow第一轮0.7、第三轮0.2。写一句话区分“可能淘汰慢热者”的逻辑可能性与“本实验淘汰了真正最优者”的实证主张。后一个主张需要补跑被淘汰候选，而且成本必须另记。

验收：列出第0份两次幸存集合；解释最后一轮180棵虽不能改变候选身份，仍要计成本。

## 7 L5 比较结果时保持配对

为每份r计算random测试MSE减grid测试MSE，以及halving减grid。一个正数代表前者更差，一个负数代表更好，0为平局。六个差值应对应同一份数据，不能拿random第0份减grid第5份。

先按方法给六份均值及样本标准差，再给差值列表、胜负平次数。样本标准差使用ddof=1，其分母为5；不要把这个量标成95%区间。若另外估计区间，应说明六份同机制模拟的限制，不能由此推广到所有任务。

本次预期均值分别3.209982、3.290078、3.219101。若你的随机搜索均值没有更好，这是正确保存的负结果，不是实验失败。不能换种子直到随机赢；如要新增机制，应先写新协议，并将新结果与本次结果分别报告。

验收：报告三路线全部六个测试结果和两组配对差；解释为什么不能按测试结果挑“最漂亮的一份”作为主要结论。

## 8 L6 记录失败与成本

failure_demo故意使用max_features=0，在接口检查阶段失败。它请求15棵但实际完成0棵，另有耗时和异常类型。这个演示独立于主要公平比较；主要522次搜索拟合与18次重拟合全部成功。

设计真实研究账本时，至少需要运行ID、方法、数据/折/种子、配置、资源、开始结束或耗时、状态、异常、已完成工作及是否重试。失败后是否允许重试、是否减少剩余机会，都要事先写明。不能把新方法的失败删除，却把基线失败当成无限损失。

实验允许显式错误抛出。试用e.mse([1,2],[1])观察形状保护，再试带NaN输入；它们应报ValueError而不是产生一个看似漂亮的小数。主审计采用显式异常检查，在python -O下仍有效，没有依赖可能被优化关闭的assert语句。

验收：说明“预留/请求的预算”“完成的树数”“实际秒数”三者不同；解释为何失败日志并不等于已成功训练15棵。

## 9 L7 真正重新执行Notebook

experiment.ipynb已经保存实际输出。打开后先浏览Markdown说明，但不要把已有输出当成你自己的运行。可用JupyterLab选择安装了依赖的内核，执行Restart Kernel and Run All；也可用本包命令行执行器：

```bash

```

执行器在新Python进程的IPython InProcessKernel里按顺序执行所有代码格，遇到错误会抛异常。它验证了Python单元执行，不等于测试了网页界面或外部Jupyter网络连接。Notebook会重新跑数值实验、审计和作图，图来自当前输出，不是读取交付目录的七张旧图。

检查每个代码格有执行计数，无error输出，七张图实际嵌入。计时图实测秒数可能随负载变化，因此图片和Notebook不要求字节完全相同；候选、MSE、预算、预测和审核结果才是稳定核对内容。

## 10 L8 写一段可以被反驳的结论

用以下要素写完整段落：目标总体是本合成机制；样本与重复规模是600行×6份；比较口径是每路线1080搜索树加60重拟合树；主要指标是自然独立测试MSE；结果包括所有方法与差值；边界是单一机制、小重复数、非等时长与非Bayesian实验。

最后另写“下一项要检验什么”。例如在新生成机制上预先比较相同墙钟预算，或给淘汰设置更高最小资源。不要把未来计划写成已经证明。也不要在同一测试集上反复迭代后继续称其封存。

## 11 常见问题与定位顺序

结果不同先检查版本、data文件SHA、种子、输入和折索引，再检查模型默认值。时间不同先看n_jobs、线程环境和机器负载。图中文字方块通常是字体问题，英文轴标签不依赖中文字体；PDF中文则需Noto CJK。PermissionError应先换可写outputs/cache位置。误删输入数据可运行generate_data.py到新目录，再比较数组，不要无记录地覆盖原件。
