## 四 循环与向量化逐项比较

先保留一个循环预测：

```python
loop_prediction = []
for value in area:
    loop_prediction.append(1.5 * float(value) + 40.0)
loop_prediction = np.array(loop_prediction)
array_prediction = 1.5 * area + 40.0
assert loop_prediction.shape == array_prediction.shape == (4,)
np.testing.assert_allclose(array_prediction, loop_prediction,
                           rtol=0.0, atol=1e-12)
```

`float(value)` 把取出的数组数值转换为普通 Python 浮点值，使循环参考的标量运算路线清楚。`assert_allclose` 不打印东西通常意味着检查通过，不是代码没有执行。若不满足容差，它会产生详细失败信息。注意我们在比较数值前先比较了形状。

依次计算预测减标签、绝对值和平均数。C 的预期结果为 `[115,130,160,175]`、`[5,0,-10,-15]`、`[5,0,10,15]`、7.5。再运行三规则比较，确认训练 MAE 的字典显示 A 为 10、B 为 0、C 为 7.5。

然后核对既定测试。面积 65、85 上，B 的预测是 140、180；标签为 144、174；绝对误差为 4、6，平均为 5。训练标签均值为 150，固定基线测试 MAE 为 15。这里只复核先前已确定结果，不用测试答案改变规则，也不把本讲披露过的数据继续当成未知封存集。

暂停思考：假如循环预测的顺序被颠倒，而数组预测保持原顺序，只比较预测均值能发现吗？通常不能，因为重新排列不改变均值。比较逐项结果才与样本对应关系有关。

## 五 让形状预测先于运行

## 六 重现一个不会自动报错的错误

这一步使用新的 `p` 与 `y`，不会修改前面的数据。先算正确 MAE，再故意把预测增加一条轴：

```python
p = np.array([115., 140., 175.])
y = p.copy()
correct = np.abs(p - y).mean()
wrong_difference = p[:, None] - y
wrong = np.abs(wrong_difference).mean()
print(correct, wrong_difference.shape, wrong)
print(wrong_difference)
```

正确结果为 0。错误差值形状为 `(3,3)`，内容是三行 `[0,-25,-60]`、`[25,0,-35]`、`[60,35,0]`，错误均值约 26.6667。请指出第 0 行第 2 列的 -60 来自什么：它是第一套房的预测 115 减第三套房的标签 175。它不是第一套房自己的误差。

然后使用 `mae_checked`：

```python
from experiment import mae_checked
try:
    mae_checked(p[:, None], y)
except ValueError as error:
    print("已按接口要求拒绝：", error)
else:
    raise AssertionError("错误形状没有被拒绝")
```

看到“已按接口要求拒绝”是这一格的正确结果。`try` 只捕获这一步预期出现的 `ValueError`；如果没有报错，`else` 会明确让测试失败。不要用一个包围整本 Notebook 的宽泛异常捕获来掩盖错误，也不要删掉检查让它“顺利结束”。

再分别传入一个二维列状标签、长度不同的标签和两个空数组，确认函数拒绝。把错误输入修回一维同形状后，应恢复正常 MAE。这里的修复依据是接口约定，不是随意试几个 `reshape`。

## 七 非方阵 单样本 与不修改输入

运行带形状契约的双特征函数，先保存一份输入副本：

```python
from experiment import weighted_predict
before = X.copy()
pred = weighted_predict(X, [2., 5.], 10.)
one = weighted_predict(X[:1], [2., 5.], 10.)
assert pred.shape == (3,)
assert one.shape == (1,)
np.testing.assert_allclose(pred, [115., 140., 175.], rtol=0, atol=1e-12)
np.testing.assert_array_equal(X, before)
```

然后只保留面积特征 `X[:,:1]`，系数改成 `[2.]`，预测应是 `[110,130,170]`。保留第二个特征轴是必要的，否则一维输入不符合双特征函数的一般契约。

故意传入 `X[0]`、长度错误的系数、`np.empty((0,2))`、包含 `np.nan` 的输入，以及列表形式的偏置 `[10.]`。每一种都应得到清楚的 `ValueError`。最后一种检查是为了要求公共偏置为单个数，而不是一个可能继续广播的数组。

为什么要用三行两列？如果只用两行两列，某些轴交换错误依然保留相同形状，可能侥幸通过形状检查。为什么还要单样本？因为整数索引可能移除样本轴。不同测试互相补充，任何单一形状都不能覆盖所有风险。

## 八 视图和数值类型的小实验

为视图实验新建数组，不要直接修改 `X`。分别创建基本切片、显式副本和高级索引结果，使用 `np.shares_memory` 检查。修改切片后，原数组应随之变化，其他副本不变。请在记录里写出“哪个索引对应同一处存储”，而不只是写“NumPy 有坑”。

整数实验采用两个明确 `int8` 的数组。`[120]+[10]` 得到 -126，而先转换为 `int64` 再算得到 130。这是故意触发的小范围演示，不可把它当作正常金额算法。再把 1.9 写到整数数组某个位置，确认保存的是 1，并解释为什么需要在赋值前选择浮点类型。

浮点实验先创建 `v = np.array([100000000.,1.,-100000000.], dtype=np.float32)`。默认求和在本讲环境中得到 0，指定 `dtype=np.float64` 累加得到 1。再把已经按 `float32` 保存的 `100000001` 转为 `float64`，观察精度损失并没有恢复。一个实验关注中间累加，另一个关注输入保存，两者不要混淆。

## 十 常见故障与处理顺序

遇到 `NameError`，先检查是否跳过了前面的定义格，重启并从头运行。遇到 `ModuleNotFoundError`，检查 Notebook 与终端环境，以及是否在本讲目录中导入 `experiment.py`。不要把相同名字的个人脚本命名成 `numpy.py`，那可能遮住真正的 NumPy 库。

遇到广播 `ValueError`，打印操作数的形状，按最右轴开始核对，不要先试转置。遇到 `AxisError` 或提示轴超出范围，通常意味着你对一维数组使用了 `axis=1`，应追查哪次索引去掉了轴。遇到输出形状变成 `(n,n)`，先看是否混用了列状预测和一维标签。

遇到 `AssertionError`，看失败的是形状、数值还是输入未修改。先恢复原始小数据，与纸笔答案比较，再考虑浮点容差。不要为让测试通过而扩大到没有意义的容差。若输出含 `nan`，检查空数组、无效数据和非法运算；它不是一个“比较大的预测误差”。
