# 第七讲实验指南

从新进程重跑一份完整基线记录

本实验把前六讲的任务、函数、数组和数据检查组成一个小型复现包。你需要完成两类检查：结果是否符合已知的合成数据计算；别人是否能只靠保存的文件与说明，从干净状态得到相同的记录。两类检查都通过，也仍不能证明现实房价预测能力。

## 一 准备固定材料

本讲需要 Python 3.11 或更新版本及 NumPy。实际验收使用的版本见 verification.json。已有 Anaconda 时，可先在自己的课程环境中运行 import numpy 检查是否存在；不要因为本实验安装 GPU 软件。若需要安装最小依赖，在已选择的环境终端执行 python -m pip install -r requirements.txt。Notebook 另外需要 Jupyter。

目录内的 data/houses.csv 是固定六十条合成房屋，data/split.csv 为每个编号指定 train、validation 或 test。config.json 保存候选与生成来源；experiment.py 执行实验；expected_result.json 保存经独立算术交叉核对的几个固定参考值。generate_data.py 只用于重建数据来源，正常复跑不要先运行它。

先在纸上写下实验约定：一行一套独立合成房屋；面积平方米；总价万元；训练36、验证12、测试12；直线参数从预定九个组合按训练 MAE 选择；常数方案用训练价格平均数；两个方案按验证 MAE 比较；测试仅评价冻结选择。先说清这些，后面的输出才有可解释含义。

## 二 用一次命令留下结果

进入本讲目录，在终端执行：

```text
python experiment.py --output results_run1
```

预期选择 linear_grid，斜率 2.0，截距 10.0。教学测试 MAE 为 4.666666666666667 万元，训练均值基线在同批测试上的 MAE 为 32.333333333333336 万元。最后一两位小数是浮点表示，正文展示可以写约 4.667 与 32.333，但保存记录保留完整数值。

这次运行会创建 results_run1/result.json。打开它，找出 counts、split_ids、configuration、training、validation、frozen_model、test_predictions、inputs_sha256、code_sha256 与 environment。不要只找到最终分数就结束：至少指认一项“决定做什么”的配置和一项“记录做出了什么”的结果。

![图 1 一个指标要能追溯到源材料。先从结果文件找到模型与测试编号，再回到配置和数据核验同一条样本。](figures/01_chain.png)

配置中的候选网格按斜率顺序、再按截距顺序遍历。程序对每个组合计算训练 MAE，分数在容差内并列时保留先前候选。当前数据的获胜直线训练 MAE 约为 4.638889；常数方案训练 MAE 约为 31.961420。它们只描述训练36条的表现，不能与别的样本集分数直接当作公平优劣比较。

## 三 手算一条训练样本和全部测试误差

H001 属于训练，面积65、标签146。对斜率2、截距10，预测为140，绝对误差6。去 result.json 中训练网格对应规则的计算过程，确认它遵循同样的乘加与误差定义。training.fitted_training_predictions 保存两个已拟合方案逐条训练预测，fitted_models 保留包含常数基线值在内的参数。九个网格候选仍保存汇总分数；需要其他候选的单条预测时，可在 Notebook 单独调用 predict，不改变训练算法。

训练价格总和为5479，共36条，所以常数基线是 $5479/36\approx152.194444$ 万元。这个数值来自训练数据，不能替换成测试价格的平均数。我们使用均值作为预定基线，不声称它是 MAE 下所有常数中的最优解。

十二条测试记录的绝对误差按编号顺序为：H003为3，H006为5，H012为7，H022为5，H024为8，H026为3，H032为1，H035为4，H039为0，H042为7，H044为8，H049为5。它们相加为56，因此测试 MAE 为 $56/12=14/3$，约4.666667。先自己相加，再与程序比较。

基线在同十二条记录上的绝对误差总和为388，平均 $388/12=97/3$，约32.333333。这两项总和使用独立的有理数算术核过，避免只用程序输出自己生成参考值再宣布程序正确。独立小核验仍不覆盖所有代码路径，但能发现单位和聚合错误。

## 四 验证集作出了哪个选择

result.json 中两个验证 MAE 应分别约为41.319444与4.75。它们来自相同十二条验证记录。直线方案因为验证 MAE 较低而被选择，随后 selected/frozen_model 保存斜率2、截距10。训练决定直线内部参数，验证决定最终方案，两层决定不要混同。

找出一条验证样本，使用 predict 与 mae 单独核算。现在提出一个反事实：如果把全部测试标签增加10000，训练与验证数据不改，选择的模型应该变吗？不应该。测试分数会变，模型选择不能因此改变。配套自检会验证拟合与选择函数只接收相应角色的数据。

所有标签在公开 CSV 中，当前实验不提供物理上的保密隔离。这里核验的是函数信息流：训练与选择函数只获得训练或验证记录。真正的研究封存还需权限、流程和记录管理，不能把一个局部函数签名当成完整安全证明。

## 五 从另一个新进程重跑

结束第一次运行后，重新执行：

```text
python experiment.py --output results_run2
python experiment.py --self-test
```

两份 result.json 在相同输入、代码与当前环境下应字节一致，因为本程序没有写入时间戳、随机运行编号或机器路径。Notebook 会读取两份结构进行比较；也可以用文件摘要工具比较。如果包含时间戳的其他程序字节不一致，不能直接认定科学结果不同，应区分元数据与所关心结果。

自检确认固定参考、角色数量、编号隔离、MAE 平移性质、测试标签不影响选择、遗漏划分拒绝、错误形状与非有限数拒绝，还拒绝不支持的并列规则、非有限或负容差、空网格及非有限候选参数。不要用 python -O，因为它会去掉调试断言。关键输入检查在函数中使用明确异常，不仅依赖 assert。

再从另一个工作目录用脚本完整路径运行，输出写到新的目录。默认数据应仍能找到，因为路径相对于脚本文件，而非终端所在位置。如果只有在某个目录下才能运行，应检查是否把相对路径错误地绑定到工作目录。

## 六 在 Notebook 中逐步走完整条链

打开 experiment.ipynb。第一格检查材料并读取固定配置；第二格展示角色数量与具体编号；随后分别拟合训练方案、检查验证比较、冻结选择、最后评价测试。之后核对参考值、实验版本摘要与一条样本手算。

正常顺序运行结束后，重启内核并全部运行。若某格依赖一个你早先在别处定义、却没写进当前文件的变量，这次会暴露出来。Notebook 使用同目录 experiment 模块，不复制两份不同核心算法；讲义解释每个函数输入输出，学生应把调用和角色对应起来。

结果中只保留必要环境版本，不打印使用者的完整个人目录，也不包含凭据、账号或外部服务。把实验公开时，检查输出与源文件一样重要：一个无害的代码单元也可能把本机路径、私有数据片段或秘密打印进已保存输出。本课使用完全合成数据，仍保持最小披露习惯。

## 七 三次受控破坏

先复制整个本讲目录，所有破坏都在副本中进行。第一次删除 split.csv 中一条编号记录，运行程序，预期收到“划分编号必须唯一，且与数据编号完全一致”的错误。这里不能自动把没写角色的样本丢掉，因为那会改变评价对象。

第二次保留原划分，在 houses.csv 中改变一个价格，再选择一个新的输出目录运行。数据摘要应变化，模型或指标也可能变化。若你试图写入之前已有结果、且输入摘要不同的目录，程序应拒绝，要求使用新输出目录。这个保护是为保留实验历史，不是不可破解的文件锁。

第三次把测试标签改变，但不改训练与验证记录，用函数级检查确认 frozen_model 不变。注意不能在正式比较中把改过的测试标签当作真实新观察；这是故障注入，用于检查程序信息流，不是一个合法的房价研究干预。

每次破坏都保留“改了什么、预期什么、实际什么、恢复方法”的四句记录。不要只把报错删除后写“修复成功”。如果预期应拒绝却继续运行，即使最终分数看似正常，也需要追查。

## 八 重建数据来源是另一个实验

想核验生成脚本时，指定一个不存在的新目录：

```text
python generate_data.py --output generated_copy
```

脚本不覆盖原 data。它读取记录的两个种子，生成六十条房屋和明确划分。当前相同 NumPy 版本下，输出与已提供 CSV 的摘要一致。跨版本或生成器实现变化时，先检查版本与算法，不把“种子相同”当作无条件保证。

如果将来研究数据波动对结果的影响，应事先定义新种子与比较规则，保留每一批新样本及结果，并把它们明确归为新的模拟实验。不要把生成后选出的最好批次替换原始数据，再仍声称模型自然表现更好。

## 九 写一份可审查的短报告

报告说明：合成任务及单位；数据版本与36/12/12划分；预定候选网格与常数均值基线；训练选择与验证选择各自结果；冻结模型在十二条教学测试上的 MAE 及逐条误差；代码、配置、数据摘要和实际环境；以及公开标签、单一合成机制、小样本和未检验现实场景的限制。

一条准确结论是：“在固定的公开合成材料和所述划分中，验证选择的直线为2x+10，测试MAE为14/3万元，预定训练均值基线为97/3万元；独立新进程复跑与记录一致。”下一句应补充它不证明现实市场能力，也不证明跨样本与环境变化的稳健性。

不要写“重跑两次代表两次独立统计实验”。两次相同输入的运行是在检查计算复现，统计证据并没有因此翻倍。这个区别会在后续概率与实验设计课程中反复出现。

## 十 加练与详细答案

问题一：结果 JSON 中为什么不强制写当前时间？解答：本讲为了演示字节一致的最小包省略时间；真实实验完全可以记录时间，但比较时要把随运行变化的元数据与实验结果分开，不能把字节相同作为唯一科学标准。

问题二：若两种方案验证 MAE 在1e-12内相同，当前约定选哪一个？解答：按 config 的顺序保留较早者，常数先于直线。容差与顺序都在看测试前规定。不是因为常数在理论上永远更好。

问题三：若把所有房屋按价格排序，再按原 split.csv 编号映射角色，会改变成员吗？解答：不会。编号映射独立于数据表当前排序；若改成按行位置切片，成员就可能改变。

问题四：训练均值约152.194444在测试表现弱，是否可以看到测试后改成测试中位数再叫同一基线？解答：不能。这会使用测试答案拟合参数，改变基线及评价的信息角色。可以另作明确标记的分析，但不能冒充原来预定的独立比较。

问题五：一个完全错误的标签文件能否被程序稳定复现？解答：可以。稳定的执行只说明相同输入得到相同输出。标签是否有意义、来源是否可靠，需要另外审计。可复现性是必要的研究习惯，不是自动真实性认证。

问题六：如何区分代码版本改变与结果随机波动？解答：先核对 code_sha256、输入与配置摘要，确认环境和执行命令；只有这些条件符合所定义的重复标准后，才讨论剩余随机性或数值差异。不要第一时间把所有不同都归因于随机种子。

本指南方法依据与工具接口核查见正文参考资料和 source-checks.json。新进程计算与 Notebook 顺序执行的实际检查范围见 verification.json。
