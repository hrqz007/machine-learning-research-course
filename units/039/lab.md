# 第039讲 独立实验指南

目标是独立复现一份优化故障报告。你要用同一四行数据核对两轮更新，发现梯度符号、广播和不稳定对数公式三种注入错误，并区分步长问题与实现问题。无需先读完整讲义即可按本指南运行，但应掌握 NumPy 形状、链式法则与批量梯度下降。

## 1 目录和运行环境

本目录包含 experiment.py、experiment.ipynb、audit.py、library_check.py、build_assets.py、data/observations.csv 和 data/experiment_config.json。requirements.txt 锁定普通运行与 Notebook 所需版本；environment.yml 是可选 conda 环境说明。PDF 的构建工具不属于学习者运行依赖。

在本单元目录打开终端，使用 Python 3.12，执行：

```text
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
mkdir results
python experiment.py --output results/report.json
python audit.py --output results/audit.json
python library_check.py --output results/library.json
```

Windows 可将激活命令换为 `.venv\Scripts\activate`。这只是操作指引，本次没有实测 Windows、Anaconda 安装过程或浏览器 Notebook 界面。作者实测的是 Linux CPU、Python 3.12.14、NumPy 2.3.5 与 SciPy 1.17.0；固定版本库检查会拒绝不同 NumPy/SciPy 版本，避免把未测语义当作已核验。

脚本按自身位置寻找默认输入，所以也可以从其他目录调用它。输出父目录需事先存在。原子写入会完整替换指定报告；源码、教学数据和已存在的单元交付文件有覆盖保护。不要把输出指向原始数据。

## 2 先验收输入再计算

Notebook 第一格必须最先执行。它核对默认数据、配置和四个执行模块的 SHA-256 全字节摘要；全部通过后，才导入数值和绘图模块、读入配置并展示结果。任何字节改变都应导致失败，包括最后一行的数字和不改变语义的尾部换行。

这种检查防止“数据改了，旧讲义表格还在”。它不能证明数据科学上合理，也不是签名系统。运行自定义试验时，复制 CSV 与 JSON，用脚本的 `--data`、`--config` 明确指定新输入并另存报告；不要只改 Notebook 的摘要来绕过默认契约。

数据必须有完整表头 `id,x,y`，行号按1至n连续，n在2至100之间，x在−100至100之间，y严格为0或1。拒绝布尔值、文本型数值、额外字段、重复行号和非有限数。JSON 重复键、NaN、Infinity 和原始数值的非零绝对值低于 $10^{-150}$ 均被拒绝。原始输入的窄范围不应重新套到合法的内部更新状态上。

## 3 实验A 手算与程序逐行对账

打开原始 CSV，确认四行依次为 $(-1,0),(0,0),(1,1),(2,1)$。令参数顺序为 $(b,w)$，初始为 $(0,0)$，学习率为1/2。每行按下面顺序计算，不跳步：

$$p_i=b+wx_i,\quad r_i=p_i-y_i,\quad \ell_i=r_i^2/2,\quad c_i=(r_i/4)[1,x_i]^\top.$$

汇总 $F=\sum_i\ell_i/4$ 和 $g=\sum_i c_i$ 后，两个参数同时减去 $(1/2)g$，再用新参数重算四行。完整两轮的关键检查点如下。

| 状态 | 参数 $(b,w)$ | $F$ | 梯度 $(g_b,g_w)$ |
|---|---|---|---|
| 0 | $(0,0)$ | $1/4$ | $(-1/2,-3/4)$ |
| 1 | $(1/4,3/8)$ | $7/256$ | $(-1/16,-1/16)$ |
| 2 | $(9/32,13/32)$ | $103/4096$ | $(-1/64,0)$ |

报告中 `paths.none.initial` 是状态0；`paths.none.trace[0].new` 是状态1；下一条 trace 的 old 必须等于上一条 new。每行记录 prediction、residual、half_square、mean_loss_contribution、全部局部导数和 mean_gradient_contribution。练习不要只比较最终参数；故意错一项平均因子，看哪一层最先不一致。

audit.py 用独立 Fraction 重算两个完整更新和三个前向状态，另用32组固定种子的二进制有理数据核对实际浮点运算，并用 Decimal 高精度多步结果作参照。这里的随机性只用于审计覆盖，不用于主训练数据或默认路径。

## 4 实验B 分离符号和广播错误

`paths.sign` 使用反号梯度，其第一候选参数为 $(-1/4,-3/8)$，配对目标升至 $215/256$。实际方向导数为 $13/32>0$。候选被拒绝后，最终已提交参数仍为 $(0,0)$；失败候选保存在 trace 中，不能丢弃。

`paths.broadcast` 故意把残差扩展成 `(4,4)`。它优化所有预测与所有标签两两配对的平均平方误差，不是原任务。它第一步为 $(1/4,1/8)$，自身目标从 $1/4$ 降至 $39/256$。它最终会接近 $(1/2,0)$，并报告自己的梯度小。请同时读取 `intended_final_evaluations.broadcast.loss`，核验它在原配对目标上的表现。

![实验图1 广播会增加12个不属于原任务的配对。黑框对应应保留的四个元素。](figures/02_broadcast_pairing.png)

验收要求：写出正确残差与错误残差的形状、两个目标的定义、首步更新和所依据的标签配对。不能用“NumPy 结果不对”作为解释，广播按其定义工作，是调用者写错了任务。

## 5 实验C 检查梯度但不迷信单一差分

报告 `gradient_checks.table` 固定在 $(0.2,-0.3)$，对每个 h 同时检查原平方目标、广播目标与稳定 logit 目标。先找到 $h=10^{-5}$ 的行。正确平方梯度应为 $(-0.45,-1.1)$，广播梯度为 $(-0.45,-0.6)$。

验收四个结论：正确梯度相对原目标通过；符号反转失败；广播梯度相对原目标失败；广播梯度相对它自己的目标通过。误差阈值应与步长、dtype、函数尺度一起报告，而非只贴一个“pass”。

![实验图2 左边读步长区间，右边读“检查的是哪个函数”。误差低不自动等于任务正确。](figures/04_gradient_checks.png)

再观察 logit 目标从 h=0.1 降到0.01时，误差约缩小100倍；接近机器尺度后又变差。平方目标沿坐标是二次式，中央差分的三阶截断项为零，不能要求它在大步长区间也表现相同斜率。

用纸笔补一项非光滑反例：在 $f(u)=|u|$ 的零点，中央商为0，左右商分别为−1、1。报告必须写“不存在普通导数”，不能把一个约定的子梯度0与中央商吻合说成可微性验证。

## 6 实验D 同一数据的数值压力试验

本节明确改用二元对数损失，不接续平方损失训练。仍使用同一 x、y，令 $z=b+wx$、$t=(1-2y)z$。稳定每行损失为 $\max(t,0)+\log(1+e^{-|t|})$，程序用 `log1p` 算最后一项。

三组参数在配置文件中逐项给出。请读取 `stability.cases` 的每一行，比较稳定结果、直接指数后对数、概率再取对数，以及“稳定softplus再减yz”四种写法。

| 参数 | 要观察的证据 |
|---|---|
| $(0,40)$ | 可表示的小正损失会被相消弄成0；概率取对数可产生NaN |
| $(0,1000)$ | 稳定公式保持有限；很小尾项下溢有明确标记 |
| $(0,-1000)$ | 自信但错误的预测应产生大而有限的损失，不能被非有限值替代 |

`library_check.py` 实际运行固定版本的 `np.logaddexp`、`scipy.special.log_expit`、`logsumexp`、`expit` 和 `scipy.optimize.check_grad`。它还用1100位 Decimal核验极端 softplus，使 $e^{-1000}$ 量级的正值不会被参考计算先抹掉。库结果保存于 library-result.json，未运行 PyTorch。

NumPy与SciPy逐点吻合只支持这些输入与语义；它不是全部浮点输入的证明。`check_grad` 是前向差分，其误差不能按中央差分预期解释。对 `(n,2)` 的 `[0,t]` 矩阵，必须说明为什么 log-sum-exp 沿 axis=1 归约。

## 7 实验E 停止标签与真实成本

读取每个 path 的 status 与 cost。默认正确路径25次提交、26次前向，广播路径30次提交、31次前向；符号和大步长失败均为0次提交但2次前向。广播每次有16个损失元素，正确配对只有4个。

`paths.tiny_step` 的学习率固定为 $10^{-12}$，首步移动很小但梯度仍约0.901，状态应为 `stagnation_gradient_large`。`paths.large_step` 固定使用10，方向导数为负但候选损失上升，状态为 `loss_increase_rejected`。

默认配置适合重现讲义数值；自定义配置的最终状态可能不同。合法的状态还包括梯度阈值满足、预算耗尽与数值失败。验收不能把这些标签合并成“结束”。如果出现NaN，停止并定位第一处非有限量，不允许用 nanmean、填零或静默删行让报告变漂亮。

## 8 真正测试拒绝路径

先在一个临时目录复制输入，然后依次做以下修改；每次只改一项，使用新的输出文件名。失败应发生在数值计算和任何输出文件创建之前。

- 把 CSV 最后一行标签改为 `1e-999`、`NaN`，或增加第四字段
- 把 JSON 最后一个压力参数改成 `true`、`1e-999`，或重复 `schema_version` 键
- 在 Python 函数调用中传入 `[0, True]` 初值或错误形状的数据
- 在副本 Notebook 的默认契约文件末尾追加一个换行，再只执行第一格

还要用 `python -O` 重做审计。如果守卫只使用 assert，优化模式会暴露问题。实际审计包含43种原始输入拒绝、6种JSON拒绝和6个新进程最后字段破坏测试，且检查回调未运行、标准输出为空、未创建结果文件。

## 9 最终需要交出的报告

报告应包含：输入与执行文件摘要；模型和每个轴的定义；两轮完整账本；差分扫描图与步长解释；三种注入错误的最小失败证据；实际更新尺度与停止原因；全部已发生调用的成本；修复方案与复测结果；环境版本和未测试边界。

不要把源码运行成功等同于验收。重新启动内核并按顺序运行全部代码格，确认每幅图是实际 PNG 输出而非只有 Figure 的文字表示。原始报告要保留；写一页摘要解释“观察到什么、哪种假设被排除、下一步改什么”。完整练习解答在 answers.pdf；自行作答后再核对。
