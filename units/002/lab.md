# 任务定义与数据生成实验

## 实验目标

这次实验不训练模型。你要核对一小包原创合成资料，回答记录对应谁、当时知道什么、标签是否成熟、不同部分有没有相同对象。先用纸笔作判断，再让 Python 重复同一套规则。如果手算和电脑不一致，追查定义与记录，不以电脑输出自动取代自己的判断。

建议用两次各约一小时完成。第一次阅读讲义并完成纸笔审计，第二次运行 Notebook、核对结果和整理报告。所需材料是纸笔、能运行 Python 的电脑与本讲完整文件夹。全部实验可离线运行，不需要 GPU、API 密钥、账号登录或下载外部数据。操作系统和界面版本不同，按钮名称可能略有变化；以“从头依次运行全部单元”的含义为准。

## 一 文件和运行结果分别在哪里

lecture.md 是主讲义，lab.md 是本实验说明，answers.pdf 与 answers.md 是练习详解。experiment.ipynb 是交互式实验本，experiment.py 是相同检查所调用的可读程序。data/raw_events.csv 保存十一行原始合成记录；data/expected_labels.csv 保存纸笔规则对应的预期标签。figures 文件夹存放讲义的原创示意图。图已随资料包提供，学习者不需要运行图像生成工具，也不用安装绘图库。

运行实验会在本讲文件夹内创建 outputs 文件夹。其中 audit_report.json 保存检查结果，event_labels.csv 保存按事件去重后的标签。它们是新的输出，原始 CSV 不会被实验覆盖。再次运行会更新同名输出文件，因此如果你要保存自己的修改实验，先把整个本讲文件夹复制一份并重新命名。

CSV 是一种简单文本文件，每行是一条记录，逗号分开字段；第一行写列名。可以用文本编辑器打开，也可以用表格软件只读查看。若表格软件想自动改变日期格式或编号，请不要覆盖原文件。Notebook 是由说明文字和可运行代码单元交替组成的文件，扩展名为 .ipynb；双击后出现一大段原始文本不表示文件损坏，说明它没有通过 Notebook 程序打开。

## 二 初次使用 Anaconda 与 Notebook

如果电脑已经装有 Anaconda，可以直接从开始菜单、应用列表或启动器打开 Anaconda Navigator。找到 Jupyter Notebook 或 JupyterLab，点击 Launch。浏览器打开的是你电脑上的编辑页面；这不表示实验需要把数据上传到外部网站。实验自身只读取本地合成文件。

如果尚未安装 Python 环境，可从 Anaconda 官方网站 https://www.anaconda.com/download 获取适合操作系统的安装包，按其安装界面完成安装；软件许可与安装权限由你自行确认。本实验只使用 Python 标准库，普通 Python 加 Jupyter 也足够。不要因为本讲就安装深度学习框架。此处只提供入口和任务级步骤，不假定每个版本的安装页面完全相同。

在 Jupyter 的文件列表里进入保存本讲的文件夹，直到同时看见 experiment.ipynb、experiment.py 和 data 文件夹。点击 experiment.ipynb 打开。若选择内核，选 Python 3。内核可以暂时理解为执行代码、暂存运行结果的 Python 工作进程；它不是文件本身。

第一次可以先读所有文字单元。然后从菜单选择 Kernel 中含 Restart 的选项，再选择 Run All 或 Run All Cells。JupyterLab 有时将“重启并运行全部”放在同一个菜单项中；Notebook 版本可能把两步分开。重启清空旧变量，从头运行保证代码没有依赖上一次遗留的状态。

代码单元左侧的 [ ] 会在运行后出现编号，例如 [1]、[2]。运行中可能显示星号。不要连点同一单元；等它完成。若想逐格阅读，选中单元后按 Shift+Enter，会运行当前单元并转到下一个。这是快捷操作，不要求你现在能解释代码中的每个符号。

最后一个单元应显示“脚本与逐步核对一致：True”。如果中间出现红色错误文字，后面的单元即使有旧输出也不能算本次通过。先看最末一行错误描述，再按本指南的排错部分处理。成功运行后按保存按钮或 Ctrl+S；保存的是代码、文字和目前显示的输出，重启内核不会自动删除磁盘上的原始数据。

若你习惯命令行，可在本讲文件夹打开 Anaconda Prompt 或终端，输入 python experiment.py 并回车。终端是一处接收文本命令的窗口。此操作执行与 Notebook 相同的核心函数，不需要抄写讲义中的全部代码。只选一种方式即可完成基本验收；两种都跑可额外核对一致性。

## 三 先写一份你自己的任务约定

在纸上写“版本 1，资料截止 2025 年 4 月 20 日”。随后用完整句子回答六个问题：一个样本是什么；每次预测何时发生；允许哪些当时可用的信息；三十天窗口是否包含第 30 天；什么证据可以判 1、判 0、保持未知；结果只说明哪些对象。

本实验的固定约定为：一行分析样本是一次挂牌；每次挂牌接收后立即预测；同日已记录的挂牌价可以读取；日期精度是天；窗口两端均包含；只在已确认窗口内成交时判 1，或完整核实窗口且无符合成交时判 0。原始材料中未来字段仅供审计，不能直接当作当时可知资料。该任务没有撤销成交的情况。

请在约定中增加一句“observed_through 表示已经有完整核实证据覆盖到的日期，本合成例假定该核实结果在该日期就可用”。真实项目若核实报告也延迟，应再记录报告到达时间；这里以显式简化维持零基础可计算性。它与 sale_recorded_at 这条逐笔成交登记通道不同，不能用尚未到达的成交记录替代完整核实证据。

## 四 手写数据字典

不要只列英文到中文的翻译。给每个字段写七项：名称、描述对象、含义与单位、来源、最早可用时间、空白含义、在任务中的角色。先写下面六个关键字段，再补其他字段。模板可以直接抄在纸上：字段名为____；测量的是____；单位是____；来自____；最早在____能读到；空白表示____；本任务用于____；检查规则为____。

area_sqm 要区分建筑面积与套内面积。list_price_wan 要区分挂牌总价与成交总价。sale_at 要区分事件发生与登记。sale_recorded_at 要说明对历史截止日的意义。observed_through 要解释何时足以判负例。event_id 要解释为什么房屋重复出现不一定是事件重复。

本资料包共有 17 个字段。raw_row_id 是导出行编号；event_id、house_id、building_id 分别标识挂牌、房屋与楼栋。listed_at 是挂牌预测日期；area_sqm 与 area_available_at 成对描述面积和它的可用日期；list_price_wan 与 list_price_available_at 成对描述挂牌价。sale_at、sale_recorded_at、sale_price_wan 描述后来成交及登记；fee_wan 与 fee_available_at 描述模拟成交后费用；views_30d 与 views_available_at 描述未来完整窗口浏览统计；observed_through 描述完整核实覆盖范围。完整示范字典在答案中。

## 五 审计记录身份

逐行读 event_id，并把每个不同编号写一次。你应得到十个不同事件。接着检查重复事件的两条内容是否完全相同，比较时忽略 raw_row_id，因为导出行编号本来不同。R01 与 R02 应组成一个完全副本组。

再读 house_id。你会发现 H01 对应 E01 和 E07。不要把它与前面的副本混为一谈：两次挂牌日期和挂牌价不同，按本讲的样本单位保留两次。为说明判断理由，画一条 H01 分别连向 E01 和 E07 的分叉，并在 E01 下画 R01、R02。

Notebook 的去重检查在发现同事件不同内容时会停止。这样设计是故意的：不知道哪条权威时，不能悄悄选一条。练习时可在副本文件夹里改一处重复行面积，重新运行，观察它报告冲突；不要在原文件夹里做这个改动，否则固定预期答案将不再匹配。

## 六 审计时间并重建标签

给十个事件分别写下窗口结束日。对于一月记录，E01 到 E06 的结束日依次为 1 月 31 日、2 月 1 日、2 月 2 日、2 月 3 日、2 月 4 日、2 月 5 日。E07 的终点是 5 月 1 日，E08 是 5 月 2 日，E09 是 5 月 3 日，E10 是 4 月 9 日。

先检查成交是否在窗口内，再检查登记是否在资料截止日之前。若没有已可见的窗口内成交，最后才问是否已经完整核实到窗口结束。这样能避免把“没有看到”直接改成“没有发生”。尤其留意 E09：材料包能让今天的你看见未来登记日期，但 4 月 20 日的重建不允许使用它。

写下十个答案，再打开 data/expected_labels.csv 对照。空白预期标签表示未知；Notebook 中 None 也是未知的 Python 表示。两者不表示 0。请为自己每次改错补一句原因，例如“忘记检查登记日期”或“把第 30 天排除了”，这比只划掉错误更有学习价值。

## 七 审计候选输入

在纸上按四类输入列出可用、未来、缺失三种状态。面积只有 E06 因晚一天录入而不满足当前时点。挂牌价十次都已可读。三十天浏览量十次都来自未来。费用七次非空且都来自预测后；另外三次为空。

这里的七次费用包括材料包中的晚登记案例。报告“七次未来费用”是在审计回顾性资料包，不是说截止日已经能合法读取七次费用。报告字段可用性时，务必写清参照的是每条样本的挂牌预测时点。

不合格特征不必导致整批资料扔掉。可以不让某列参与当前输入，把它留作审计或标签来源；对 E06 的面积需要明确缺失策略。本讲只报告问题，不偷偷替你训练一套缺失值处理办法。

## 八 审计分组与时间范围

坏划分的训练事件为 E01、E02、E03、E05，测试为其余事件。分别写出两边房屋编号的集合、楼栋编号的集合，并找交集。房屋交集应为 H01；楼栋交集应为 B01、B02、B03。

另一划分把 B01、B02、B03 中全部事件放在训练，B04、B05 中全部事件放在测试。楼栋交集为空，但测试只有 E10 一条已知标签，E08、E09 未知。因此“没有重叠”并不等于“评价足够有说服力”。如果有人把空交集直接解释为可靠模型，这一步正好提供反例。

按时间的演示把 3 月 1 日当作冻结日。历史部分是 E01 到 E06，这时它们的标签证据已经充分；后续部分为 E07、E08、E09、E10。这里按挂牌日期划分，同时检查训练标签在冻结日是否可得。你可以观察：H01 仍横跨前后，所以“面向未来”与“面向新房屋”是两种不同的检查。代码不拟合模型，也不给这几个例子计算可泛化性能。

## 九 核对数值与最容易误读的输出

固定资料应得到 11 条导出行、10 次事件、9 套房屋、5 栋楼。去重后标签为 5 个 1、3 个 0、2 个未知；已知八条中的正例比例为 62.50%。去重前已知九行里有六个 1，比例为 66.67%。这两项分母不同，既不是同一个统计，也不是总体成交率。

非法费用捷径的回顾性算术误差为 0 万元，valid_prediction 明确为 False。它提醒我们零误差可以出现在不合法的输入上。不要在实验报告中把它写成“模型达到完美预测”。我们没有训练这样的模型，更没有用真正不可见的未来资料做部署评价。

边界检查一共有九项：第 30 天计入；第 31 天排除；随访不足未知；核实证据晚到时未知；延迟登记改变可知状态；第 0 天计入；预测尚未发生时未知；同事件冲突版本拒绝；完全没有已知标签时不除以零。通过九项只说明这些指定规则按预期运行，不代表检查覆盖所有现实错误。

## 十 做两个受控修改

第一次修改只改变资料截止日。Notebook 预留单元会比较 E09 在 4 月 20 日和 4 月 23 日的可知标签，分别为未知和 1。解释时要说“我们现在得到了登记证据”，不要说“模型改变了历史”。E08 在本材料包中仍缺少完整窗口证据；单纯把截止日期调到很远的未来不会自动补出未提供的随访。

第二次修改只改变窗口边界测试，而不动原始文件。阅读边界测试中第 30 天与第 31 天的日期，先在纸上计算，再运行对应测试。若你想尝试 60 天任务，应复制整个项目并同时更新任务约定、函数、预期标签与说明；只改一处数字后继续引用旧报告，会把不同任务混在一起。

## 十一 常见问题

如果提示 No module named experiment，说明 Notebook 没在与 experiment.py 相同的目录启动，或文件没有完整复制。回到 Jupyter 文件列表，确认两个文件同层，再关闭错误页面、重新从该目录打开。不要把本机绝对路径抄到代码里作为首选修复，那会降低文件夹可迁移性。

如果提示找不到 raw_events.csv，确认 data 文件夹存在且文件名没有被系统改成 raw_events.csv.txt。解压时保留目录结构。若提示日期格式错误，检查是否用表格软件重存了原始 CSV；用未修改的备份恢复，再运行。

如果出现 AssertionError，程序的预期核对没有通过。可能是你有意修改了数据，也可能是运行版本不一致。先保存错误信息和修改记录，恢复原始材料并重新启动内核运行全部。不要直接删除 assert 行来获得“成功”。assert 在这里的作用是自动要求某项结果符合预先给定的规则。

如果单元一直显示星号，先等待片刻；本实验只有十个事件，通常很快结束。若长时间不结束，可从 Kernel 菜单停止或重启，再从头运行。不要把旧输出当作本次运行的结果，也不要因为浏览器页面还开着就断定内核仍在正常执行。

## 十二 交付与验收

提交自己的任务约定、至少六个关键字段的手写数据字典、十个事件的标签及理由、候选输入可用性清单、重复与分组交集结果，以及一段不超过三百字的结论。Notebook 输出与 outputs 文件可作为计算证据附上，但不能代替文字解释。

结论必须包含三项限制：数据完全合成；已知标签比例不等于目标总体比例；无重叠和自动检查通过都不足以证明现实部署效果。最后回答一个反事实问题：“如果我只留下已经成交的记录，主任务会丢掉谁？”如果能说清这点，你已经开始从文件走向数据生成过程。

## 执行核验说明

制作阶段实际执行了 Python 脚本、Notebook 全部代码单元和九个边界测试，并比较二者报告一致。受执行环境禁止套接字限制，Notebook 使用真实 ipykernel 的进程内内核顺序执行，保留了输出；未在学习者的浏览器界面测试，也未验证普通 Jupyter 外进程内核传输。这不影响随附代码的离线标准库计算，但不同本机安装环境仍需按以上步骤核对。

运行时不要添加 Python 的 -O 优化选项；它会移除本教学程序用于核验的 assert。代码检查仅覆盖本讲明确列出的合成数据约定，不是可直接部署的生产数据审核系统。
